# 03. 정책서 — LidAwake

## 1. 권한 정책 (비밀번호 없이 sudo를 쓰는 방식)
- 앱 안에 비밀번호를 **저장하지 않는다.**
- 대신 최초 1회, macOS 관리자 인증 창을 통해 아래 sudoers 규칙 하나만 설치한다.
  ```
  # /etc/sudoers.d/lidawake  (root:wheel, 0440)
  <사용자명> ALL=(root) NOPASSWD: /usr/bin/pmset -a disablesleep 0, /usr/bin/pmset -a disablesleep 1
  ```
- **허용 범위는 위 두 명령으로 고정한다.** 다른 pmset 옵션이나 다른 명령은 여전히 비밀번호가 필요하다.
- 설치 전에 `visudo -cf`로 문법을 검사하고, 검사를 통과하지 못하면 설치하지 않는다. (sudoers 파일이 깨져서 sudo를 쓸 수 없게 되는 사고를 막기 위함)
- 규칙은 설치한 사용자 계정에만 적용된다.

## 2. 상태 정책
- 진실의 원천(source of truth)은 앱 내부 변수가 아니라 **`pmset -g`의 `SleepDisabled` 값**이다.
- 터미널 등 다른 경로로 값이 바뀌면 다음 클릭 시점에 다시 읽어서 맞춘다.
- `disablesleep` 값은 재부팅 후에도 유지된다. 앱을 다시 실행하면 그 값을 읽어 아이콘에 그대로 표시한다.

## 3. 종료 정책
- 앱을 종료(우클릭 → 종료, 로그아웃, 시스템 종료)하면 **잠자기 방지를 해제(0)**한다.
- 이유: 아이콘이 사라진 상태에서 방지가 켜져 있으면, 사용자가 이 사실을 잊고 가방에 넣을 위험이 있다.
- 단, 앱이 강제 종료되거나 비정상 종료되면 복구되지 않는다. 다음에 실행할 때 덮개 열림 아이콘으로 표시된다.

## 4. 안전 고지
- 덮개 열림 아이콘 상태에서 덮개를 닫은 채 **가방에 넣으면 발열과 배터리 소모가 생긴다.** 이동할 때는 꼭 덮개 닫힘으로 바꾼다.
- 잠자기 방지는 화면 꺼짐을 막지 않는다. 덮개를 닫으면 화면은 꺼지고 시스템만 계속 동작한다.

## 5. 실패 처리
| 상황 | 동작 |
|---|---|
| 비밀번호 창에서 취소 | 아무것도 바꾸지 않음, 알림 없음 |
| 규칙 설치 실패 (visudo 검사 실패 등) | 경고창에 오류 메시지를 표시하고 상태는 그대로 유지 |
| 규칙 설치 후에도 pmset 실패 | 경고창 표시, 아이콘은 실제 상태로 다시 맞춤 |

## 6. 설치 (Gatekeeper)
- 유료 Apple 개발자 계정($99/년)이 없어서 공증(notarization)을 받지 않은 **ad-hoc 서명** 앱이다.
- 그래서 처음 실행하면 "확인되지 않은 개발자" 경고가 뜬다. 다음 중 한 가지 방법으로 1회만 허용하면 된다.
  1. 시스템 설정 → 개인정보 보호 및 보안 → 맨 아래 "LidAwake" 옆 **그래도 열기**
  2. 터미널에서 `xattr -dr com.apple.quarantine /Applications/LidAwake.app` 실행
- 나중에 개발자 계정이 생기면 Developer ID로 서명하고 공증을 받아 이 단계를 없앤다.

## 7. 제거
1. 앱을 종료한다 (잠자기 방지 자동 해제).
2. `LidAwake.app`을 휴지통에 버린다.
3. 권한 규칙을 삭제한다: `sudo rm /etc/sudoers.d/lidawake`
